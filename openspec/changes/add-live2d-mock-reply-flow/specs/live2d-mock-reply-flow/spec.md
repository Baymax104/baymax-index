## ADDED Requirements

### Requirement: 提交后创建助手回复流程

系统 SHALL 在用户提交非空消息后追加用户消息，并为本次提交创建一条助手回复消息。

#### Scenario: 非空消息触发回复流程

- **WHEN** 用户在 Live2D 对话框输入非空内容并提交
- **THEN** 消息列表显示该用户消息
- **AND** 消息列表显示一条新的助手消息进入回复流程

#### Scenario: 空白消息不触发回复流程

- **WHEN** 用户提交空字符串或仅包含空白字符的内容
- **THEN** 系统不追加用户消息
- **AND** 系统不创建助手回复消息

### Requirement: 助手回复先显示思考状态

系统 SHALL 在生成 mock 回复内容前，将新助手消息展示为思考状态。

#### Scenario: 提交后展示思考状态

- **WHEN** 用户提交非空消息后 mock 回复内容尚未开始输出
- **THEN** 对话框中的助手消息显示思考中的视觉状态

#### Scenario: 思考状态结束后进入输出状态

- **WHEN** mock 回复的思考延迟结束
- **THEN** 该助手消息不再保持思考状态
- **AND** 该助手消息开始展示回复内容

### Requirement: 助手回复使用打字机效果展示

系统 SHALL 使用打字机效果逐步展示 mock 助手回复内容，并在输出完成后将该消息标记为完成。

#### Scenario: 回复内容逐步出现

- **WHEN** 助手消息处于打字输出阶段
- **THEN** 对话框逐步增加该助手消息的可见文本内容

#### Scenario: 回复输出完成

- **WHEN** mock 回复文本已经全部展示
- **THEN** 该助手消息显示完整回复内容
- **AND** 该助手消息进入完成状态

### Requirement: 回复过程中禁止并发提交

系统 SHALL 在助手回复处于思考或打字输出阶段时阻止新的消息提交。

#### Scenario: 回复过程中提交控件不可用

- **WHEN** 助手回复处于思考或打字输出阶段
- **THEN** 用户不能提交新的消息

#### Scenario: 回复完成后恢复提交

- **WHEN** 助手回复完成
- **THEN** 用户可以再次提交新的非空消息

### Requirement: 收起对话框不取消回复流程

系统 SHALL 在对话框收起时保留当前回复流程，并在对话框再次展开时显示最新消息状态。

#### Scenario: 思考时收起并重新展开

- **WHEN** 助手回复处于思考状态且用户收起再展开对话框
- **THEN** 对话框显示该助手消息的当前状态

#### Scenario: 打字时收起并重新展开

- **WHEN** 助手回复处于打字输出阶段且用户收起再展开对话框
- **THEN** 对话框显示该助手消息当前已经输出的内容或最终完整内容

### Requirement: Mock 回复来源可替换

系统 MUST 将 mock 回复内容获取逻辑封装在可替换边界内，以便后续接入大模型 API 时复用对话 UI 和回复生命周期。

#### Scenario: 回复流程通过 provider 获取文本

- **WHEN** 系统需要生成助手回复文本
- **THEN** 回复流程通过独立 provider、函数或等效边界获取 mock 回复内容
- **AND** Live2D 对话面板组件不直接硬编码完整回复生成逻辑

### Requirement: 移动端保持不显示

系统 SHALL 保持 Live2D 人物和对话框只在桌面端显示，mock 回复流程不得导致移动端加载或显示 Live2D 交互。

#### Scenario: 移动端不显示回复 UI

- **WHEN** 页面在不满足桌面端媒体查询的视口打开
- **THEN** Live2D 人物、对话框和 mock 回复流程 UI 均不显示
